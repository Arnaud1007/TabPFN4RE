# ADR 0033: exact NYC same-publisher row concordance

Date: 2026-09-30
Owner: project implementation
Affected requirements: US04, US05, US06, US07, US08, US22, US23, US24
Protocol: `nyc-dof-same-publisher-row-concordance-v1`
Status: frozen design executed; exact concordance not demonstrated

## Evidence and scope

The [v3 worksheet inspection](../runs/u0-nyc-worksheet-inspection-v3-20260930T092659Z/report.md) structurally qualified Bronx, Brooklyn, Queens and Staten Island. Manhattan failed because of one formula in its preamble and remains outside this protocol. The [pinned rolling API CSV](../runs/u0-nyc-rolling-snapshot-20260928T225512Z/snapshot.json) has SHA-256 `84c06057c52a2822f982cd98fb77ef7edf2c14134d00f46b073d2e4b762b2ef2`; the official XLSX capture manifest has SHA-256 `e29928b44a1b1f733219dac86b8d7e18704bf8c301b458afc2bf1a53895bb9e2`. Their four in-scope borough counts agree at 6,424, 23,041, 26,461 and 6,866 respectively, totalling 62,792 rows per source. Count agreement is not row identity or economic-transfer evidence. The captures occurred on different days and do not establish first availability of individual rows.

The question is whether the same publisher's two captured representations contain exact corresponding rows in those four boroughs. This is a source-concordance diagnostic, not a transaction eligibility or model dataset release. It cannot certify close dates, sale consideration, individual dwellings, reuse rights, historical availability or any sale label. The [200-record NYC manual review](../runs/u0-nyc-review-sample-20260928T234700Z/report.md) remains at zero completed.

## Frozen inputs and checks

Use only the pinned private CSV snapshot and five-file XLSX capture above; open only the four v3-qualified XLSX workbooks for comparison. Validate the CSV manifest, capture manifest, selected file hashes, and the prior v3 private result and hash manifest against their recorded digests. Do not invoke v3 replay here because it would reopen excluded Manhattan; run the v3 validator on each selected workbook in the new scan instead. Write this run's intent before the first source row read. Enforce private-root ACL, no reparse points or hard links, and same-handle pre/post hashes for every source. Preserve the v3 ZIP/OOXML inventory, printer-settings, exact worksheet MIME, relationships, defused XML, decoded-size, row/cell/string, date and formula controls. A changed source, structural failure, timeout or unsafe path fails the run without a valid aggregate. Use local files only: no network, workbook application, formula execution or package extraction. Pin the environment and code identity.

Use the 21 ordered API fields. Map only the XLSX header name at column G from `EASEMENT` to `EASE-MENT`; leave every row value unchanged. Require XLSX column A borough code to agree with its named borough. Require the CSV header and field count exactly. Preserve source row ordinals in the protected result, never in tracked output. Require 82,345 CSV rows, with 19,553 Manhattan rows and exactly 6,424 Bronx, 23,041 Brooklyn, 26,461 Queens and 6,866 Staten Island rows; require those four workbook counts independently. Count unknown or unexpected borough rows and then fail the run if nonzero. Manhattan is excluded from the matching denominator, not silently discarded. Equal borough counts do not establish row identity.

## Exact comparison

Trim outer Unicode whitespace from every source string; make no other value conversion in v1. Do not coerce numeric block/lot codes, remove leading zeros, reformat date or money strings, case-fold addresses, round amounts, or infer missing apartment numbers. An empty apartment number is an explicit blank marker and remains distinct from a nonempty value. If source representations format the same date or price differently, v1 records a mismatch; a later normalization experiment needs a new decision and run.

For each borough, compare the multiset of complete 21-field tuples and report the matched and residual row counts per source. Separately group rows by the exact six-field candidate key `(BOROUGH, BLOCK, LOT, APARTMENT NUMBER, SALE DATE, SALE PRICE)`. A key is incomplete when borough, block, lot, date or price is blank; apartment may be blank. A key occurring once in each source forms a unique comparison pair. Classify its full-row agreement, address agreement and building-class-at-sale agreement independently. A key repeated in either source is ambiguous: retain both multiplicities and do not pair its rows arbitrarily. Report CSV-only and XLSX-only **complete-key** groups/rows, source-specific incomplete-key rows, source-specific duplicate groups/rows, multiplicity-discordant groups and uniquely paired rows with explicit reconciliation of every source row. Full-row multiset residual rows are a separate measure, not a subset of source-only key rows. Date or price formatting differences can make the keys unpaired; v1 cannot attribute those mismatches to formatting or compare their address/class fields. Full-row multiset equality and unique-key concordance answer different questions; neither proves a unique economic transfer.

Keep source strings and candidate keys in memory only while comparing one borough at a time; cap aggregate resident raw cell characters at 32 million per scan and fail closed on overflow. Private, Git-ignored artifacts may contain row ordinals, source side, status and SHA-256 fingerprints for manual tracing, but no raw address, unit, price or key value; cap the serialized private result at 64 MiB. Public output contains only fixed-category counts by borough, frame totals, input hashes, protocol and limitations. Publish no row ordinals, row/key hashes, addresses, apartment identifiers, prices, dates or examples. Suppress an entire dependent breakdown for a borough if any positive category cell is 1–4; omit dependent subtotals, percentages, booleans, statuses and overall comparison totals that could reconstruct a suppressed borough cell. Zero and source row denominators may be shown. Preserve private full counts and the suppression reason. Every output states `label_status: unqualified` and `sale_labels_certified: 0`.

## Execution and acceptance

Write synthetic RED tests first for byte/manifest/path/ACL tampering, malformed OOXML, wrong borough, exact header alias, blank apartment, leading-zero codes, differing date/price formatting, duplicate and unequal-multiplicity groups, incomplete keys, address/class disagreement, CSV/XLSX-only groups, small-cell suppression, interruption and offline replay. The private run is create-only. Write intent before row reads, mark interrupted runs incomplete, write private/public canonical JSON and a hash manifest atomically, then independently recompute both for replay. Keep failed attempts. Code review, Python review and security review must pass; focused branch-aware coverage must exceed 80% per new module, full suite, Ruff and scoped dependency checks must pass. Commit and push reviewed code before the first private row-comparison read.

Passing this protocol means only that the frozen same-publisher extracts agree to the reported extent. Source rights, actual close-date meaning, first row availability, transfer/parcel/unit identity and manual review remain independent U0 blockers. No result from this protocol alone admits a training label or advances G-US.

The cause and any economically equivalent record linkage remain open for a new versioned diagnostic. Zero labels were admitted.
